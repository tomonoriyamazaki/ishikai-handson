## 今回の学び（前回からの発見）
 
### ファイル名と「中身の名前」は別物
前回はxschemが書き出した `.subckt inverter_yamazaki` とGDSトップセル名 `inverter` の不一致でLVSが失敗し、sedで修正した。今回は `cp` でファイルを複製してファイル名だけ `_yamazaki` に変更したところ、LVSは何のエラーもなく通過。LVSが照合するのはファイル名ではなくセル名/subckt名であり、`cp` は中身に一切触れないため名前ズレが起こり得ない。「ツールで新規保存すると中身の名前が動くことがある。シェルのコピーなら動かない」という切り分けができた。
 
### スナップ設定とオフグリッド地獄
表示・ルーラー用スナップが0.005µmになっていたため、マウス操作した図形が製造グリッド(0.05µm)に乗らず、DRCでOFFGRID違反268件が発生。さらに「Snap to grid while moving」は移動量を丸めるだけで、元がオフグリッドの図形は平行移動してもオフグリッドのままという罠も踏んだ。グリッドを0.1µmに設定し直し、レイアウトを作り直して解決。環境設定は作業前に確認すべし。
 
### レイヤー名の罠（NW ≠ WN）
PMOS群を囲む井戸をNWレイヤーで描いてDRC 36件。講師に確認したところ正しくはWNレイヤーで、修正により大半が解消。同様に「GC」もゲートコンタクトの略ではなく独自のゲート系レイヤーだった。プロセスごとのレイヤー命名は思い込みで判断しないこと。
 
### エンクロージャの意味を体で理解
- コンタクト/VIAはM1のベタで包む必要がある（cont_g・via_1の両方に共通）。これが不足するとV1-GCスペーシング等の違反として現れる
- WN井戸は内側（タップから5µm、AP拡散から7µm）と外側（ガードリングのAPから5µm）の両方から制約され、正しい幅のレンジに収める必要がある
- サンプルの「余裕のある配置」は美観ではなく全てルール由来。DRCエラーを読み解くことが、サンプルがその形をしている理由の答え合わせになる
### フロアプランの入口
サイズ制限（300×500 / 800×500）は、トップレベルで各ブロックに敷地を割り当てるフロアプランそのもの。prBoundaryレイヤーがその境界枠に相当することを知った。
